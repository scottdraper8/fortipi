# v0.1.0 integration evidence

Acceptance requires the final composed source, its retained candidate archives,
the three actual native operating systems, and the applicable deployed targets.
Paid backend verification remains pending while work continues without Workers
Paid. Free validation preserves the full backend scope and cannot satisfy paid
JavaScript or Linux runtime claims.

The trusted release coordinator invokes the import-safe `runEvidence` export or
the equivalent CLI. Candidate preparation finishes before installed-client
evidence starts. The fixed fixture is nonsecret and cannot select fewer claims.

```sh
node tests/clients/run-evidence.ts local --candidate "$FORTIPI_CANDIDATE_MANIFEST" --fixture tests/clients/fixtures/local.json --out dist/evidence/local
node tests/clients/run-evidence.ts native --candidate "$FORTIPI_CANDIDATE_MANIFEST" --fixture tests/clients/fixtures/local.json --out dist/evidence/native
node tests/clients/run-evidence.ts live --candidate "$FORTIPI_CANDIDATE_MANIFEST" --deployment "$FORTIPI_DEPLOYMENT_RECEIPT" --fixture tests/clients/fixtures/local.json --out dist/evidence/live
```

Each fresh output directory contains individual claim JSON, `results.json` and
one `v0.1.0-claims.md` table. Rows bind source, candidate, assets, image, lock,
toolchain policy, environment, actual producer, deployment, command, seed,
observations, independent oracle, sensitivity and limits. Detailed logs remain
ignored. Required failure, timeout, unavailable evidence or a missing row prevents
the passing gate. Native raw gates retain the claim ID `portable-daemon` and
exactly their actual platform; release aggregation authenticates all three.

The coordinator issues and publicly revokes ephemeral application/executor
roles. Client children receive only their scoped role. The TUI uses its normal
protected profile and an ephemeral client credential file in a fresh private
directory. Credentials, ticket URLs, model content and environment dumps are
excluded from evidence. Pending or unknown revocation remains blocking.

| Evidence boundary       | Required observation                                                                                                     | Limit retained in the result                                                             |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| Durable state           | Actual Pi/workerd/SQLite, acknowledged interruption, same storage and canary, original tasks/receipts/events             | Local process death proves disk recovery; platform eviction requires platform evidence   |
| Workspace and execution | Independent file hashes, actual Computer/native effects, receipt/CAS, consent, fencing, uncertainty and replacement      | Separate roots on one host do not prove separate live devices                            |
| Clients                 | Retained five-pack normal installs, browser native transports, TUI keys/current cells and independent stdlib Python      | A successful build or test-process exit cannot replace the public outcome                |
| Security and models     | Exact retained review/source/legal inputs, real CP/model factories, generation races and actual deployed Workers AI task | Synthetic provider peers do not prove external provider/OAuth or paid service success    |
| Sensitivity             | Disposable single-site faults, actual behavioral falsifier and restored pass                                             | Compilation failure, crash, timeout or an unreached site cannot count as a killed mutant |

The parent's canonical build report records current source qualification and
outstanding producer handoffs. Release acceptance comes from the authenticated
final candidate evidence, native jobs, deployed checks and independent review.
