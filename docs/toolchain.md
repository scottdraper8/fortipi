# Toolchain and dependency policy

Use Node **26.13.1**, pnpm **12.23.0**, TypeScript **7.0.2** and Biome **2.6.8**. CI uses exact versions and SHA-pinned setup Actions. Retain older binaries for historical source reproduction; use the reviewed versions for current work. Python **3.15.2**, pre-commit **4.7.0** and Go **1.27.4** support the required third-party hooks/native build; maintained implementation is TypeScript. Node's native stripping does not typecheck: `tsconfig.tools.json` checks automation, generators and Node/browser/PTY tests; the Worker project checks its own context and private fixtures. Public contract/browser projects have no ambient Node types.

Node [26.13.1](https://nodejs.org/en/blog/release/v26.13.1) is the [2026-11-11 security release](https://nodejs.org/en/blog/vulnerability/november-2026-security-releases) fixing HTTP/2, TLS/HTTPS and other runtime vulnerabilities. The official Darwin arm64 archive and signed SHA-256 list were verified using the active Node release key; bundled npm remains **11.20.0**, without a separate npm installation. Product minimum engines and exact build/asset/consumer guards require the patched host runtime. Historical image source-kit metadata and embedded image Node have separate recorded identities and security qualification.

The management CLI advertises exactly Node **26.13.1**, matching its pinned
Wrangler runtime guard. Other public packages retain their existing minimum
engine policies; build, maintainer and installed-consumer checks remain exact.
The CLI does not claim support for another Node release without qualification.

The Worker uses `skipLibCheck: true`, matching [Cloudflare Agents' configuration](https://github.com/cloudflare/agents/blob/main/docs/agents/configuration.md#typescript-configuration). The pinned Pi/Computer declaration graph brings Node globals into Workers types and otherwise produces duplicate-library diagnostics. The tools project also uses this setting because the pinned schema generator's parser declarations conflict internally with `exactOptionalPropertyTypes`. This skips declaration-file internals, including any future local `.d.ts`, while TypeScript still checks maintained `.ts` implementation, generated contract source and boundary fixtures against the real imported types. Root and public package projects retain declaration checks. Keep actual runtime/bundle validation and negative consumer fixtures; this setting cannot establish that Node APIs work in Workers or validate dependency declaration internals.

Release's registry verification uses Node-bundled npm **11.20.0** at its declared path/version. This is an external verification tool, not another product dependency. Reserved scope `fortipi-ci-test` is always nonpublishable: it may build/test the actual PR/feature SHA, while actual-scope release operations retain all trusted-main/tag/source/API gates. Synthetic receipts can never authorize deployment/publication.

The builtin-only installer resolves the native pnpm executable and verifies its exact version before installation. On Windows it discovers the official package's `pnpm.exe` rather than executing a shell shim. The pinned setup Action retains its older bootstrap package after self-update; read the generated shim's final `cmd-shim-target` data marker to locate the active engine, require its exact package identity, then probe its version outside the project so automatic version switching cannot mask an old binary. Native verification sends one PTY input challenge and checks both real TTY output and rendered terminal cells; all three operating systems still require their own CI observations.

After observing the child's genuine exit and rendered output, release PTY listeners and the terminal in `finally`. Windows additionally needs node-pty's public `kill()` to dispose its ConoutConnection worker after natural child exit; leaving that worker referenced kept CI alive even after its assertions passed. The three-minute native step deadline verifies that the verifier itself exits normally. Never force a successful process exit to hide outstanding handles.

Registry signatures are verified against public npm keys; published provenance availability is recorded. Refresh via `pnpm run review:supply-chain` (`review-supply-chain.ts --locks --check`) before policy/candidate gates. This writes only ignored `dist/supply-chain/advisory-review.json`, binding the fresh result to both lock hashes and the reviewed policy hash. Pin checks reject changed inputs or stale results. CI therefore leaves the candidate source tree clean. Only serialized dependency review intentionally uses `--locks` without `--check` to update tracked archive policy. Sigstore transparency verification remains release evidence. An empty npm OSV response is bounded evidence; Git-only CVE records can disagree, as recorded below.

Minimum release age stays 1440 minutes, with strict trust and dependency-build enforcement. Same-day exclusions name exact reviewed identities and expire at publication + 24 hours in review metadata; remove aged exclusions and relock. No wildcards, ranges, alternative approval mechanisms or `permissions.build` overrides. Only exact esbuild **0.28.2** and node-pty **1.1.0** may execute lifecycle scripts. Reviewed unnecessary workerd, pnpm shim, Google 2.32.0 no-op, core-js banner and protobuf warning scripts are explicitly denied. Optional integrity-locked native artifacts remain installed. Fresh source builds must show pinned node-gyp; unknown scripts fail.

The selected published SDK cohort is Pi family **1.6.0** and Agents **0.34.0** (2026-11-20). `patches/retired-pi16.json` binds each former patch intent to the exact upstream archive/member and immutable official source that now covers it; historical patch/source-policy records remain for audit. No active SDK patch remains. Required transitive SDK identities are OpenAI **7.59.0** and Google GenAI **2.32.0**; the latter publishes no provenance and its exact no-op lifecycle is denied. Application/API and whole release qualification remain separate.

Direct dependency pins live in the root and workspace `package.json` files and `pnpm-lock.yaml`; external tooling has its own manifest and lock. Computer npm/source attribution and the native-image recipe have separate identities and qualification. A package update must preserve historical image/source records.

## Licenses and distribution boundaries

Own code uses the exact root Sustainable Use License. The product allowlist remains MIT, Apache-2.0, MIT OR Apache-2.0, BSD-2-Clause, BSD-3-Clause, ISC, 0BSD, BlueOak-1.0.0, Unlicense and CC0-1.0. `license-policy.json` adds only parent-reviewed exact identities: argparse **2.0.1** Python-2.0, argparse **3.0.4** PSF-2.0, postal-mime **2.7.6** MIT-0 and caniuse-lite **1.0.30001823** CC-BY-4.0. Retain complete source licenses/copyrights, author/source and unmodified/change status; CC-BY data receives no SUL restriction. License expressions are not simplified.

Cloudflare runtime versions are pinned together in the Worker/CLI manifests and frozen lock, with corresponding runtime guards. `patches/review.json` records each active dependency transformation, its immutable upstream sources, patch hash and original/effective file hashes. Retain the signed upstream archive identity separately from the effective bundled and installed bytes, and convey modification notices and license texts. Embedded bundled code needs advisory review in addition to the resolved npm graph. Workerd postinstall remains denied. Exact age reviews, credential separation, Free capability gates, native-platform evidence and deployed qualification remain required.

CLI → Wrangler → Miniflare → Sharp is a separately spawned deployment tool chain. Native Sharp/libvips components stay external. Standard dependency bundles have their own authenticated file plan and notices. Their Markdown/BLAKE3 WASM members are limited to the exact identities, bytes and attribution recipes enforced by `scripts/check-licenses.ts`; conservative Rust source notices remain an upper bound rather than a compiled inventory. Other embedded components retain their own exact attribution records under `tools/unstale/licenses/`. No arbitrary WASM or additional native/npm edge is authorized. **External-tool/native hashes and Worker metafiles still prohibit these tool bytes in owned package dist, Worker output, CLI worker-assets/templates and images.** Dependency-plan permission preserves the separate owned-output conveyance guards and release/installed/platform evidence requirements.

The exact packaging sources are [sharp-libvips ebb95f8](https://github.com/lovell/sharp-libvips/tree/ebb95f8add54eee8bed840e3fb587e4cbec857d7) and [sharp 51a990f](https://github.com/lovell/sharp/tree/51a990faa26ade5586a4934ac9673c98d8893326). Preserve per-platform archive `versions.json` and README, plus pinned [component notices](https://github.com/lovell/sharp-libvips/blob/ebb95f8add54eee8bed840e3fb587e4cbec857d7/THIRD-PARTY-NOTICES.md), [POSIX](https://github.com/lovell/sharp-libvips/blob/ebb95f8add54eee8bed840e3fb587e4cbec857d7/build/posix.sh), [Windows](https://github.com/lovell/sharp-libvips/blob/ebb95f8add54eee8bed840e3fb587e4cbec857d7/build/win.sh) and [WASM](https://github.com/lovell/sharp-libvips/blob/ebb95f8add54eee8bed840e3fb587e4cbec857d7/build/wasm.sh) source recipes. Any future conveyance fails closed pending full applicable GPL/LGPL/MPL/Apache/MIT texts, exact corresponding component sources/patches/build/relink material and replacement proof; generic links/version strings are insufficient.

`check-licenses --foundation` verifies actual archive bytes and produces deterministic ignored `dist/supply-chain/inventory.json` plus original texts for release tooling. Missing archive licenses use explicit exact attribution records and hash-checked upstream source texts. Data-uri's complete MIT text is in its archived README. Future bundles/packs/images require actual file/module inventories and notices, even if metadata passed. External unstale remains separate AGPL tooling and is never a product dependency.

In `tools/unstale/platform-tools.json`, the global `reviewedAt` preserves the original catalog review. A later per-record `reviewedAt` dates only that record’s scoped source, pin and license review; it does not renew other records or establish runtime qualification.

## Build and runtime interfaces

`build`, `typecheck`, `lint`, `schema:check`, `check:pins`, `check:licenses`, `unstale:check`, `test`, `test:executor`, `test:browser` and `test:pty` are unconditional integration commands. Missing generators, sources, tests or assets fail. Foundation acceptance checks existing tools/configuration without fabricating product implementations.

Browser and PTY commands invoke the same complete `run-evidence.ts local` runner; pass its required `--candidate PATH --fixture PATH --out DIR` arguments. Run the combined local evidence once in CI, rather than infer success from files containing no Node tests. Native executor CI uses `build:executor` then `typecheck:executor` for the actual contract/executor sources before real platform tests. It runs `verify-foundation.ts --native` for native binaries without depending on unrelated unbuilt SDK/TUI/CLI exports. The policy job builds all packages before the unconditional foundation/global tooling and workspace typechecks; all test/tool sources remain covered there.

`candidate:local` calls the release owner's synthetic-scope producer. Its stdout is exactly `{schemaVersion:1,candidateManifestPath,candidateSha256}`; the wrapper checks the saved file's hash and repository containment, records the receipt and exports the actual path to subsequent CI steps. `tests/clients/fixtures/local.json` is the evidence owner's static nonsecret descriptor. Order is source/unit/runtime checks → candidate build/notices/pack without recursive installed tests → one full local evidence run → artifact/hooks gates. Missing producer, receipt, descriptor or claims fails.

Build order: contract `generate.ts` → compile contract/client/TUI/executor → actual Wrangler `deploy --dry-run --outdir dist/worker --metafile dist/worker/metafile.json` → CLI `package-worker-assets.ts --worker-build apps/worker/dist/worker --commit-sha FULL_SHA --version 0.1.0` → CLI compilation. Assets preserve actual chunks/WASM/specs/licenses; no mock entrypoint. `package.json#fortipi.publishNames` is the sole source-to-personal-scope map for release staging, which rewrites imports/declarations and internal versions as well as names. [Cloudflare's compatibility documentation](https://developers.cloudflare.com/workers/configuration/compatibility-flags/#enable-requestsignal-for-incoming-requests) requires the first flag before 2026-11-17; forwarding code must also pass `request.signal` explicitly. ## Cloudflare infrastructure policy

`FORTIPI_CONFIG.infrastructure` follows contract-owned `InfrastructurePolicy`: version 1, `profile:free|verified`, `accountPlan:unknown|free|paid`, capability observations and finite `bounds`. Unknown/Free defaults: object 128 MiB, install 512 MiB with 25% repair headroom; file 4 MiB, snapshot/staging 16 MiB, 512 entries, 8 retained versions, retained workspace 64 MiB; inline output 32 KiB, artifact 1 MiB, job output 8 MiB; 2000 events/8 MiB per conversation; one active mutating job, four queued; 30 requests/principal/minute, 120/install/minute; SQL pages 100, transfer concurrency four. Metadata checks exact defaults; contract owns schemas and source owners enforce admission, reservations, retained bytes, backpressure and recovery.

Both [Dynamic Workers/Loader](https://developers.cloudflare.com/dynamic-workers/pricing/) and [Containers](https://developers.cloudflare.com/containers/) require paid capability selection. A paid account alone raises no bounds. Discovery cannot promise shared account headroom. Count Pi/Computer/history/index/outbox/scratch overhead, preserve completion/revoke/repair capacity and admitted identities. Daily Cloudflare exhaustion has a documented UTC reset/backoff where known; storage has no daily reset. Preserve old revisions and uncertainty; never replay an attempted side effect. Runtime receives no deployment credentials. This covers Cloudflare infrastructure only: **no model/provider hourly, weekly or token budgets**. Supported provider authentication remains intact; optional `FORTIPI_MODEL_AUTH_KEY` belongs to contract/Worker credential handling, never foundation secret collection.

## Hooks, CI and unstale

Keep all existing integrity/secret/size/conflict/YAML/JSON/link/case/private-key hooks. New hooks check real tooling, exact policies, Biome, all project types, schema drift, bundles and external unstale on manifest/lock changes. Biome excludes protected authorities/access files and original third-party license texts; it never rewrites them. Security-only Dependabot keeps zero version PR limits for root npm, isolated unstale and Actions; parent verifies repository security settings.

The Biome hook covers maintained TypeScript, JSON, YAML and Markdown. Its exact `packages/fortipi-contract/openapi.yaml` exclusion preserves the generator's compact JSON syntax under the 500 KiB file cap; the unconditional schema drift gate checks those generated bytes. Source schemas, generator and contract README remain formatted and checked.

CI runs on pushes to `main` and pull requests. Every job starts with SHA-pinned harden-runner and explicit endpoints; checkout retains no credentials. Linux jobs request block mode and require the agent service before checkout. The CI `native-executor` and Release `native` matrices request audit mode on hosted macOS and Windows, matching the [vendor's supported capabilities](https://github.com/step-security/harden-runner/blob/aebdcf6156ab6691adf63218240e476564a1ed4c/README.md#environment-compatibility-matrix). All three operating systems retain their product tests. These two matrices have only read permissions and receive an ephemeral GitHub token for their final health check. That check reads current-job metadata and reported failure annotations once, without polling or exposing messages. It requires a current configuration and an activated, enabled macOS extension, or a matching current-job Windows process and archive-verified executable. These observations establish installation/activity; loaded policy and event delivery remain unverified. Reported installer failures cannot pass health verification. All other jobs retain block mode. Linux registry controls and the unallowed-destination probe record request behavior; generic rejection alone does not establish policy attribution. CI/browser/image/three-OS/live results require their actual observations.

Use folded YAML `>-` for space-separated endpoint tokens: the pinned agent misparses embedded newlines from literal `|` lists. Pin checks reject internal CR/LF after trimming the scalar; the folded-to-literal fixture reproduces the observed bootstrap defect.

The image gateway distinguishes `policy-connect-refusal` from `policy-redirection`; only the former sets `refusalVerified`. The existing strict `ECONNREFUSED` oracle remains. Redirection requires the original HEAD request's identity, ALS-bound connector/socket creation and all one-to-four native TCP attempts to StepSecurity's pinned sinkhole on443, then matching socket/connector/request error objects and the original fetch rejection with a native connect timeout. Shared connector timers need not retain ALS; exact object identity binds their terminal errors. A pooled connection, concurrent request, extra socket, unknown endpoint, DNS-only result, abort or incomplete six-event trace stays UNKNOWN. Both proofs still require stable host namespace, upstream policy DNS and application authority before/after, plus allowed200 controls. No observer changes request arguments, dispatchers, promises or I/O. Only fixture deadlines change: gateway12s, HTTPS client15s, namespace child75s, above the native10s connector deadline. Local tests substitute loopback endpoints/classification and installed connector tooling; they do not qualify actual Linux/gvisor-tap-vsock policy enforcement. Generic namespace/container failures are labeled failed-or-timed-out, never refusal.

`run-unstale.ts` verifies isolated Unstale **0.3.1** native bytes/version, personal initialization, supported notify/status/sync/advisories and records report/coverage hashes independently of exit status. It never chooses a provider or starts a model step. The existing 150-second coverage bound is retained from the actual 0.3.1 `onboarding::Bound` contract (60-second minimum, twice that hard limit, plus public-request startup/shutdown headroom). No model review or global agent integration is launched. It passes no registry/application credentials, inherits home paths unchanged and preserves personal decisions. Coverage/service gaps are explicit degraded observations with bounded retry; missing tool/setup and actionable security findings fail.
